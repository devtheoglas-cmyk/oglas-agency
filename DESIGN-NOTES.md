# Design notes

- Vend Sans is commercial and has been substituted with the self-hosted Schibsted Grotesk (display) + Bebas Neue (wordmark) families, as required by the build specification. The owner can replace the display face later by updating the font files and `@font-face` declaration. **Confirmed against the live production site (theoglas.com)**: it is a published Figma Sites export, whose DOM contains an invisible `selectable-text-layer` (transparent, Manrope-fallback spans) purely for accessibility/SEO — that layer is NOT the visual rendering and must not be used as a font reference. The real visual wordmark is clearly condensed (matches Bebas Neue), confirmed via a full-page screenshot of the live site.
- Routes match production exactly: `/about` (nav label "People") and `/contacts` (nav label "Contacts") — not `/people` / `/contact`.
- Footer "Send E-mail" → `hello@theoglas.com`; LinkedIn/Instagram/Behance all link to their generic root domains (`linkedin.com`, `instagram.com`, `behance.net`), all live/clickable on production — confirmed via the real site's anchor `href`s (`<a>` hrefs are reliable ground truth on this site, unlike computed text styles).
- "Web Development" (capital D) confirmed from a live screenshot, fixed in both the Home "What we do" accordion and the Services page list.
- "brand PLATEFORMS." on the People/`/about` founder statement is **intentional** — it is the actual live copy on production (confirmed via screenshot), not a typo to correct. Do not "fix" this spelling.
- Home, Works, People/`/about`, and Contacts have each been visually confirmed against full-page screenshots of the live site (owner-supplied): section order, copy, work-card grid, filter pills, contact form fields/placeholders, office blocks, and footer wordmark all match.
- All six designed routes (Home, People/`/about`, Services, Works, work detail `/works/fishwala`, Contacts) plus `/privacy` and 404 are fully built per `BUILD-SPEC.md`, not placeholders. `tsc -b`, `eslint`, and `vite build` all pass clean.
- **Home page "Shared Success" client marquee rebuilt**: production actually shows a **3-row grid of large client logos** (each row an independently-scrolling marquee track), not the single thin row of small logos this project originally had — confirmed by downloading the actual raw Figma-export PNG slices the production site serves at `https://theoglas.com/figma/slices/oglas-home-NN.png` (see below). `LogoMarqueeRow`/`SharedSuccess` in `src/pages/Home.tsx` now render 3 stacked rows with larger logos (`h-12 lg:h-16`, alternating scroll direction).
- **`public/assets/clients/gymkha.webp` was a corrupted/mis-cropped asset** (showed only a stray "|A" fragment, not the Gymkha logo) — re-extracted a clean crop of the real "◇ GYMKHA" wordmark from the production slice PNG and replaced it.
- **Display heading weight bumped from `font-semibold` (600) to `font-extrabold` (800)** across every page's primary h1/h2 headings — confirmed by rendering "CREATIVITY" in both Schibsted Grotesk 600/700/800/900 locally and comparing letterforms/stroke-weight directly against the production slice PNG; 800 was the closest match (Schibsted's "R" leg curve also matched production far better than Manrope's, confirming the font-family choice too).
- **Home page section vertical spacing matched to production to within 0.7%** (15,006px vs production's 15,116px at 1440px viewport width; started at 12,148px / 80.4%), via a repeatable, precise (not eyeballed) method: a Playwright script scrolls the full page, then does a DOM `TreeWalker` text search for ~20 known heading/label strings (`"SINCE 2019"`, `"REFRAME"`, `"SHARED SUCCESS"`, `"USERFLOW"`, `"SEE HOW WE CAN HELP"`, etc.) and reports each one's `getBoundingClientRect().top + scrollY`. Running the identical script against production and the local build gives exact per-segment pixel deltas, so `py`/`mb`/`mt`/`gap-y` values on `Hero`/`VisualsFelt`/`WorkShowcase`/`ShowcaseBand`/`WhatWeDo`/`SharedSuccess`/`BuildBoldly` in `src/pages/Home.tsx` could be tuned segment-by-segment against a real target instead of guessed uniformly. The hero heading in particular had been going the *opposite* direction — it was rendering too large — caught only because this method measures both over- and under-shoot per segment, not just total page height. One remaining known imprecision: the hero segment still slightly overshoots (~158px) while the `WhatWeDo` segment slightly overshoots too (~270px) — netting out close to zero overall, but not per-segment perfect. Re-run `measure3.js` style scripts (see this file's history / ask for it) against both sites to keep refining if needed.
- **How to get pixel-truth for this site going forward**: theoglas.com is a Figma Sites publish (see the reference-source note below) — its homepage visual layer is literally full-bleed PNG slices at `https://theoglas.com/figma/slices/oglas-home-00.png`, `-01.png`, … (increment until 404; each covers a fixed vertical band, `<img>` elements in DOM order/top-position). Downloading these directly gives an exact, authoritative pixel reference — better than any screenshot — for measuring exact spacing, cropping logo assets, or checking colors. Other routes likely have their own slice sets (e.g. `oglas-about-NN.png`, `oglas-works-NN.png` — not yet confirmed, check via the same `getBoundingClientRect`-based DOM query for `img[src*="figma/slices"]`).
- **Home page final spacing/type pass: 100.4% match** (15,170px vs production's 15,116px). Two remaining `clamp()` headings were found miscalibrated by measuring actual rendered *text width* (via a DOM `Range.getBoundingClientRect()` on the exact text node, not the container) against the same word's ink-width measured directly from the production slice PNG (careful: that section's slice has **black text on white**, unlike the hero's white-on-black — get the brightness threshold direction right or width measurements come out nonsense/full-width): (1) `VisualsFelt`/`SharedSuccess` shared heading class (`"Visuals created to be felt"`, `"Shared Success"`) was rendering **17% too wide** for its cap-height — fixed by shrinking the clamp (`5vw,4.5rem` → `4.4vw,4.1rem`) and tightening tracking (`-0.03em` → `-0.055em`). (2) `WorkShowcase`'s giant display headline (`"CREATIVITY"`/`"CHANGE"`/`"REFRAME"`/`"INTERACTION"`) was the opposite — **24% too narrow** — because its `clamp(3rem,11vw,13rem)` never reached the 13rem ceiling at a 1440px viewport (11vw only computes to 158px); bumped to `clamp(3rem,14.5vw,13.5rem)` so it now sits right at ~209px, matching. Lesson: when a heading looks "off" relative to a reference image, measure actual rendered text width via `Range`, not just font-size or eyeballing — the two bugs here were opposite in direction and neither was obvious from font-size alone.
- **`WorkCard` (`src/components/ui/WorkCard.tsx`) fixed per owner screenshot comparison**: caption (year/name/subtitle) was lime-on-hover-only styling with a serif-ish display font — should be plain **white, uppercase, body font (Manrope)** at all times, only turning lime on hover; and the image was `object-cover` on a `bg-charcoal` panel, which crops full-context source assets (billboards-in-frame, phone-in-hand mockups) at the edges — switched to `object-contain` on `bg-dark` so the complete source image shows uncropped. Applies everywhere `WorkCard` is used (Home grids, `/works`, "more work" on the Fishwala case study).
- **`SharedSuccess` marquee direction pattern**: rows now alternate right/left/right (`reverse` on rows 1 and 3, forward on row 2) per the owner's explicit direction spec, not the arbitrary alternation from the earlier 3-row rebuild.
- **`WhatWeDo` accordion**: all five items (`Brand Design`, `Web Design`, `Digital Marketing`, `UX/UI Design`, `Web Development`) are now expandable dropdowns — the last four were static non-interactive rows before, per the original `BUILD-SPEC.md` claim that "no content was designed" for them. The owner asked for them to be real dropdowns; added a reasonable, on-brand description paragraph for each (this is placeholder-quality copy the owner should review/replace, not verbatim production content like the rest of the site — there was no production source for these four panels to match against).
